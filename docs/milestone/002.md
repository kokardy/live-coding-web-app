## 病院予約システム向けテーブル設計

患者情報や予約データは「外部システムから連携される前提」とする。

- `patients` (患者情報)
  - id, name, patient_number (診察券番号など)
- `reservations` (予約情報)
  - id, patient_id, specialty, start_time, end_time
- `specialty` (診療科)

## Alembic セットアップ

- `alembic init` で初期化
- `alembic.ini` と `env.py` の修正
  - SQLAlchemy の `Base.metadata` を読み込ませる
  - 環境変数からDB接続URL（PostgreSQL）を取得するように設定
- 初回のマイグレーションファイルを作成
  - `alembic revision --autogenerate -m "create patients, and reservations tables"`
- マイグレーションの実行
  - `alembic upgrade head`

## FastAPI の実装方針

- ディレクトリ構成の整理
  - `core`: アプリ全体で使う共通設定やユーティリティ
  - `core/logger` : ロギング設定
  - `domain/models`: ドメインモデル（ユーザー、患者、予約などのエンティティ定義）
  - `domain/infrastructure`: インフラ抽象クラス
  - `infrastructure`: DBアクセスや外部APIクライアントなどの具体的な実装
  - `presentation` : HTTPルーティング
  - `usecase` : ビジネスロジック

---------

## 今回実装する API エンドポイント

外部連携データであることを踏まえ、今回は参照（GET）をメインとする。
編集(POST, PATCHなど)は内容は今後追加予定

- `GET /health`
  - サーバー稼働確認
- `GET /reservations`
  - 予約の一覧・スケジュール取得

---------

## 動作確認

- サーバー起動後、手動またはスクリプトでテストデータを投入する
- Swagger UI (`http://localhost:8000/docs`) から API を叩いてみる
- Docker コンテナ内の PostgreSQL でデータが正しく引けているか確認する
  - `docker compose exec postgresql psql -U APP_DB_USER -d APP_DB_NAME`
